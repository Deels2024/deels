# Ограничения подозрительных аккаунтов

## Жизненный цикл

1. Rate limiter помечает аккаунт `is_suspicious = true` и устанавливает `suspicious_blocked_until` на один час.
2. Ограниченные действия до указанного времени возвращают HTTP 403. Каждая такая попытка увеличивает `suspicious_violations`; в сообщении выводится оставшееся время в часах или минутах.
3. После истечения `suspicious_blocked_until` middleware снимает временную отметку `is_suspicious` и пропускает действие. Счётчик нарушений сохраняется.
4. При третьей запрещённой попытке аккаунт получает `suspicious_moderation_pending = true`. Автоматический срок блокировки больше не применяется; доступ восстанавливается после ручной модерации.
5. Успешное подтверждение email или телефона снимает подозрительный статус, часовую блокировку и ручную модерацию, а также обнуляет нарушения.

## Ограниченные действия

- отправка личных сообщений;
- лайки и дизлайки;
- жалобы;
- добавление в друзья и подписки;
- публикация комментариев и лайки комментариев.

## Ответ HTTP 403

```json
{
  "success": false,
  "error": "Ваша активность слишком великая, наш сервер перегрелся и ему нужно отдохнуть. Все возможности восстановятся через 1 ч.",
  "message": "Ваша активность слишком великая, наш сервер перегрелся и ему нужно отдохнуть. Все возможности восстановятся через 1 ч.",
  "need_actions": {},
  "shouldShowEmailPrompt": false,
  "shouldShowPhonePrompt": false,
  "suspicious_blocked_until": "2026-07-17T13:00:00+03:00",
  "suspicious_retry_after": 3600,
  "retry_after": 3600
}
```

Если аккаунту требуется контакт, `need_actions` содержит один из ключей `need_email`, `need_email_verify`, `need_phone`, `need_phone_verify`; соответствующий `shouldShow...Prompt` равен `true`.

Метод `GET /api/user/{id?}` дополнительно возвращает в `data` поля `need_actions`, `suspicious_blocked_until` и `suspicious_retry_after`.
