# Deels — функциональные разрывы нового дизайна

Цель: сохранить визуальный эталон `Deels2024/deelsweb`, но поэтапно вернуть весь функционал существующего Laravel `Deels2024/deels`.

## Пакет 1 — Личный кабинет и социальные разделы — ПЕРВЫЙ ПРОХОД ГОТОВ

Возвращены в новый интерфейс через единый блок «Мои разделы»:
- мои челленджи;
- мои сторис;
- мои копилки;
- кошелёк;
- сообщения;
- мои лайки;
- друзья;
- подписки;
- подписчики;
- автоплатежи;
- благодарности / «Спасибо».

Следующий уровень: пройти каждую целевую страницу на mobile, empty/error states и действия.

## Пакет 2 — Копилки — ПЕРВЫЙ ПРОХОД ГОТОВ

Публичная копилка:
- О сборе;
- Донатеры;
- Обновления;
- FAQ.

Управление своей копилкой:
- Основное;
- Награды;
- Обновления;
- FAQ.

Существующие донат, автоплатёж, лайк, follow, чат, share, health, сторис и платежные сценарии не заменяются.

Следующий уровень: формы наград/обновлений/FAQ, состояния доната и payment result.

## Пакет 3 — Челленджи и баттлы — ПЕРВЫЙ ПРОХОД ГОТОВ

Существующая Laravel-логика сохранена и сделана явной в новом detail-screen:
- приглашения участников;
- принять / отклонить приглашение в баттл;
- join / leave / rejoin;
- reporting / отчётность;
- полезные сторис;
- выбор победителя создателем;
- журнал выполнения;
- battle reports;
- owner actions;
- приватность и visibility;
- ритм и чек-ин.

Следующий уровень: проверить все состояния участника/владельца/админа и finished/invited/private.

## Пакет 4 — Кошелёк и платежи — ПЕРВЫЙ ПРОХОД ГОТОВ

В новый UI возвращены разделы:
- движения;
- billing;
- donate history;
- автоплатежи.

Существующие пополнение, вывод, ограничения вывода, статусы и платежная логика не заменяются.

Следующий уровень: визуально пройти deposit/withdraw modals, ошибки, pending/success/failed и App Store / coins состояния, где применимо.

## Пакет 5 — Профиль и социальный граф — ПЕРВЫЙ ПРОХОД ГОТОВ

В новый профиль встроены существующие:
- реферальная программа;
- достоинства / титулы;
- место среди донатеров;
- процент от донатов;
- статистика приглашённых;
- таблица реферальных начислений.

Followers / followings / friends / likes возвращены через «Мои разделы».

Следующий уровень: публичный профиль, follow/message actions и empty states.

## Пакет 6 — Сообщения и уведомления — ПЕРВЫЙ ПРОХОД ГОТОВ

Новый UI явно поддерживает существующие:
- список диалогов;
- unread counters;
- системную кнопку уведомлений;
- поиск по чатам;
- жалобу / блокировку;
- read states.

WebSocket/Firebase backend hooks не заменялись.

Следующий уровень: реальный обмен сообщениями, reconnect/error states и mobile fullscreen chat.

## Пакет 7 — Auth и безопасность — ПЕРВЫЙ ПРОХОД ГОТОВ

Сохранены и визуально интегрированы:
- email verification code;
- phone field / существующие phone verification flows;
- reset password;
- social auth;
- Telegram WebApp auth;
- reCAPTCHA;
- anti-bot telemetry;
- honeypot `contact_url`;
- обязательные юридические согласия.

Следующий уровень: пройти validation/server errors, resend code и восстановление пароля.

## Пакет 8 — Модерация и админка — ПЕРВЫЙ ПРОХОД ГОТОВ

Добавлен permission-driven «Админ-центр», который строится из фактического Laravel `.admin_menu` и поэтому не расширяет права.

Он объединяет существующие разделы:
- stories moderation;
- challenge/battle moderation;
- ответы;
- campaign moderation;
- comments;
- users;
- games;
- payments / transactions / withdrawals;
- complaints;
- tags;
- logs;
- newsletters / statistics;
- settings и другие пункты, которые Laravel уже разрешил текущему администратору.

Следующий уровень: поочерёдно привести таблицы, фильтры, moderation actions и bulk states к source-style.

## Этап 2 — глубокая функциональная проверка

После первого прохода по всем пакетам задача меняется: теперь каждая функция тестируется по состояниям, а не только по доступности из нового UI.

Порядок:
1. Auth / guest flows.
2. Challenge/battle participant flows.
3. Story/feed interactions.
4. Campaign/donation flows без проведения реального платежа.
5. Wallet validation без реального вывода.
6. Messages/unread/reconnect.
7. Profile/social graph.
8. Admin/moderation roles.
9. Mobile 375/390/430, tablet, desktop.

## Правило миграции

1. Не менять бизнес-логику без необходимости.
2. Сначала переиспользовать существующий route/controller/service.
3. Новому дизайну давать доступ к функции через Blade/CSS/JS.
4. На каждый пакет добавлять smoke-check route contracts.
5. `main` и production не менять без отдельного разрешения.
